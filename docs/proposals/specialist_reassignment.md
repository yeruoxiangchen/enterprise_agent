# 专业 Agent 任务重分配方案

状态：已纳入 `business_multi_v6` 与 `business_v6_external_v1` 候选；功能验收使用CPU脚本模型，真实模型的总体收益待新版本评测。

实现说明：接收隐含于正常的首次执行决定；发现领域不符时才返回拒绝/转派，不为每个任务增加一次独立模型调用。中文知识Agent可在首次决定中请求 `request_reassignment`；CRM专业Agent在首次结构化结果中给出 `reject_domain`。宿主预检可读取授权资料，业务写入开始后禁止转派。单Agent使用同一执行控制，无跨专业转派。

## 目标

初次路由发生领域误判时，允许专业 Agent 在调用业务工具前拒绝不属于自身领域的任务，由协调器重新分配。一次任务最多重分配两次；三个专业领域依次排除，避免在同一领域间循环。

## 执行流程

1. 协调器创建任务，记录任务编号、用户原文、当前领域、已尝试领域与重分配次数。
2. 专业 Agent 在执行工具或业务写入前返回结构化接收决定：`accept`、`reject_domain` 或 `needs_clarification`。拒绝时给出简短原因，可以建议领域。
3. 程序校验接收决定。仅领域不符触发重分配；资料不足、工具失败与用户条件不足分别走各自的处理流程。
4. 协调器从尚未尝试的领域中选择下一领域。领域建议仅作为候选，程序禁止分配给已经拒绝的领域。
5. 最多允许两次重分配，即最多尝试三个不同领域。候选耗尽或任务含义仍不明确时，请求用户澄清。
6. 重分配前保存状态。日志记录任务编号、来源领域、目标领域、拒绝原因与次数；恢复后沿用已尝试集合及次数。

## 与业务授权的关系

领域匹配与写操作授权分别检查。专业 Agent 接收任务，不能自动获得创建工单的权限；写入仍须满足当前用户意图、动作范围及字段校验。工单草稿、用户确认和管理员处理保持各自的状态转换。

重分配只能发生在尚未产生业务副作用时。已经创建草稿或执行其他写入的任务，应通过业务回执和幂等记录继续处理，避免向另一 Agent 再次提交同一动作。

## 最小验收场景

- 首次领域误判，第一次重分配后成功处理。
- 连续两个领域拒绝，第三个领域接受。
- 三个领域均拒绝，返回澄清请求，任务结束。
- Agent 建议已尝试的领域，程序阻止循环。
- 专业 Agent 接受任务但用户未授权建单，创建工具仍被限制。
- 领域检查输出不合法或请求中断，不执行业务写入；恢复后重分配次数不归零。

后续实现应将接收校验与调度控制分开：模型负责建议，程序负责次数、候选领域、状态和业务授权。
